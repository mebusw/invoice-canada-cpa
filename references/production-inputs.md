# 生产环境输入处理

`SKILL.md` 「生产环境必须防御」一节的详细展开。**触发条件**：输入是客户实际提供的图片/PDF 批次（而非策划好的测试集），或遇到签购单、小费、退款、多页 PDF、一图多票、非 CAD 币种等场景。

## 0. 生产输入的根本特点

| 维度 | 生产输入的现实 |
|---|---|
| 文件名 | `IMG_4523.jpg` / `WhatsApp Image ...jpeg` / `扫描件_001.pdf`，**无业务信息** |
| 文档类型 | 收据 / 签购单 / 对账单 / 无关图片**混杂** |
| 重复 | 重复上传、重复拍摄、签购单与收据配对 |
| 完整性 | 模糊、反光、遮挡、截断 |
| 交易类型 | 含退款、小费、押金、分期、多币种 |
| 外部锚点 | **仅法定税率**（生产环境没有 ground truth 文件名） |

**不要从生产文件名解析任何业务字段**。即使看到 `IMG_4523.jpg`，也只把它当作 SHA-256 输入。

## 1. 文档分类（doc_type）

提取前必须先判定。三类文档的处理方式完全不同，混淆会直接产生错误的费用行。

### receipt（收据）—— 正当的费用来源

特征：有商品明细行、有税额分行（HST/GST/PST 标签）、有商户地址。

### signature_slip（信用卡签购单）—— 支付凭证，不是独立费用

特征（命中 2 项以上即判定）：

- 含 `AUTH / APPROVAL / APPR CODE / REF #` 等授权码
- 含 `MERCHANT COPY / CUSTOMER COPY / CARDHOLDER COPY`
- 含 `TIP / GRATUITY` 空行或手写数字
- 含 `SIGNATURE / X_______` 签名栏
- **无商品明细**，只有一个总额
- 含卡号掩码 `**** **** **** 1234`

### statement（对账单）—— 不可作为费用来源

特征：多笔交易列表、有 `STATEMENT PERIOD / PREVIOUS BALANCE / PAYMENT DUE` 等字样、有账户号。

**硬规则**：`statement` **绝不逐行提取为费用**。对账单是核对工具（用于发现漏传收据），不是源始凭证。CRA 审计要求的是原始收据，对账单行不能替代。若客户只提供了对账单，输出应为「缺失凭证清单」而非费用行。

## 2. 签购单与收据配对（防重复入账）

同一笔消费常有两份凭证：商户打印的明细收据 + 信用卡签购单。**各算一行会让费用翻倍。**

### 配对键

```
(vendor_normalized, date, total, card_last4)
```

`vendor_normalized`：去除大小写、空格、门店编号后缀。支付网关会改写商户名 —— `SQ *COFFEE SHOP`（Square）、`TST* RESTAURANT`（Toast）、`SP TIENDA` 等前缀需剥离后再比对。

### 配对后的处理

| 情况 | 处理 |
|---|---|
| 收据 + 签购单，金额相同 | 保留**收据**为主记录（有明细，可判 GIFI）；签购单 `doc_id` 写入 `supporting_doc` |
| 收据 + 签购单，签购单金额更大 | 差额即**小费**（见第 3 节）。主记录仍为收据，`tip` 单列，实际扣款以签购单为准 |
| 只有签购单 | 保留为费用行，但无明细 → GIFI 只能靠商户名推断，`confidence` 降低、`review_required = true` |
| 只有收据 | 正常处理 |

**不要靠时间戳配对** —— 签购单与收据的打印时间可能相差数分钟，且部分收据不含时间。

## 3. 小费（tip / gratuity）

### 为什么它同时破坏两道闸门

小费**不计税**。若把小费并入 `subtotal`：

```
真实：  subtotal 100.00, HST 13.00, tip 18.00, 实付 131.00
误算：  subtotal 118.00, tax 13.00 → 实际税率 11.0%
```

11.0% 低于安大略法定 13%，落进税率闸门的「混合篮子」分支 → **被判为 NOTE 通过，错误被伪装成合理**。餐厅是全额计税业态，本不该出现混合篮子。

### 正确处理

- `tip` 单独成列，**不进 subtotal，不进 tax 基数**
- 勾稽公式：`subtotal - discount + tax + tip = 实付金额`
- 税率闸门只用 `tax / subtotal` 计算，**分母不含小费**
- 小费属于餐饮支出的一部分 → GIFI 仍为 **8523**，同样受 ITA 67.1 的 50% 限制
- 手写小费识别度低，三工具常读错 → `tip_source` 必须标注；读不出时以（签购单总额 − 收据总额）反算，标 `DERIVED`

**餐厅收据出现低于法定税率的实际税率时，第一怀疑对象就是小费混入。**

## 4. 退款与负数

识别关键词：`RETURN`、`REFUND`、`CREDIT`、`VOID`、`REVERSAL`，或总额本身为负。

- **保留负号**。`abs()` 会让退款变成新增费用，批次总额虚增两倍退款额
- 勾稽公式对负数同样成立：`-100 + (-13) = -113` ✓
- 税率闸门用绝对值计算比率，但金额保留原符号
- GIFI code 与原消费相同（退的是什么就冲减什么）
- `VOID`（撤销）与 `REFUND`（退款）不同：`VOID` 表示原交易未成立，若原收据也在批次中，**两者都应剔除**而非一正一负

## 5. 一图多票 / 重复拍摄

### 一张图片包含多张小票

常见于客户把几张小票摊在桌上一次拍完。检测信号：图片中出现多个「商户名 + 总额」区块，或多条明显的纸张边界。

- 能可靠拆分 → 拆成多个 `doc_id`，`source_file` 相同、`page_no` 递增
- 不能可靠拆分 → **标 `review_required`，不要只提取最清晰的那张**。只报一张会静默丢失其余费用

### 同一收据被拍多次

`file_hash` 查不出来（像素不同）。按（商户 + 日期 + 总额）配对；命中且两者都是 `receipt` 类型 → 保留质量较高的一张，另一张标 `duplicate_of`。

**注意真实的重复消费**：同一天在同一家咖啡店买两杯咖啡是合法的两笔。金额完全相同且时间相近时才判重复；若收据含时间戳且相差较大，视为两笔独立交易。存疑时标 `review_required` 交人工判断，**宁可标记也不要静默合并**。

## 6. 多页 PDF

先判断结构，再决定拆分策略：

| 结构 | 判定信号 | 处理 |
|---|---|---|
| 一张发票跨多页 | 页脚 `Page 1 of 3`、末页才有 TOTAL、页眉商户一致 | 合并为**一个** `doc_id`，金额只取末页汇总 |
| 多张独立凭证 | 每页各有独立商户与总额 | 按页拆分为多个 `doc_id` |
| 对账单 | 交易列表 + 期初期末余额 | `doc_type = statement`，不提取费用 |

**最危险的错误**：把「一张发票跨多页」当成多张凭证，导致中间页的小计被当作独立费用重复入账。判据是**末页是否有全局 TOTAL** —— 有则前面各页的小计都不是独立费用。

## 7. 图像质量不足

模糊、反光、遮挡、截断时，三个工具会**各自编造不同的数字**。

- 三者对同一字段给出互不相同的值 → **不要投票选多数**（三个错误值里没有正确答案），标 `confidence < 0.5`
- 关键字段（total、tax、date、vendor）任一 `confidence < 0.5` → `review_required = true`，输出建议「重新拍摄」
- 部分遮挡导致 total 不可见但明细可见 → 可由明细求和推导，标 `DERIVED`，但仍需人工确认

## 8. 币种与汇率

- `currency` 必填，从币种符号、税种标签（HST/GST 仅加拿大）、商户地址综合判定
- 非 CAD → **跳过税率闸门**（境外税率不同），并在报告中记录跳过原因
- 非 CAD → 必须附 `fx_rate` 与 `fx_date`。CRA 一般接受交易日汇率或年均汇率，口径需全批次一致
- 境外增值税不可抵扣，计入费用总额

## 9. 押金、附加费、分期

| 项目 | 计税 | 处理 |
|---|---|---|
| 押金（瓶罐押金等） | 通常**不计税** | 单列，不进计税基数；退还时冲减 |
| 环保费 / levy（如轮胎 $20） | **计税** | 计入 subtotal，属费用一部分 |
| 服务费 / service charge | 通常计税 | 计入 subtotal（与小费不同，小费不计税） |
| 分期付款 | — | 按合同总额入账，非当期扣款额；未付部分计入应付 |

**服务费与小费的区别**：强制加收的 service charge（如大桌 18% 服务费）通常计税且计入 subtotal；自愿给的 tip 不计税。收据上两者都可能写作「gratuity」，以**是否被计入税基**为准反推。

## 10. 生产批次的输出差异

除标准三 sheet 外，生产批次应追加：

| Sheet / 区块 | 内容 |
|---|---|
| `Exceptions` | 所有 `review_required = true` 的行，按 confidence 升序 |
| `Duplicates` | 配对结果：签购单-收据对、重复拍摄、重复上传 |
| `Skipped_Gates` | 每行跳过了哪些闸门及原因（尤其税率闸门） |
| `Missing_Documents` | 若提供了对账单：对账单上有但无对应收据的交易 |

`Missing_Documents` 是对账单的**正确用法** —— 用它发现漏传的凭证，而不是用它生成费用行。
